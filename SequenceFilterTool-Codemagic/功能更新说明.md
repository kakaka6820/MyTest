# 序列过滤工具更新

## 输入5场后先获取ABCD

填写5个不同的正整数主场次号及期号（或09-10、260910、20260910形式的日期），停止输入约0.8秒后自动获取。默认依次尝试500、澳客，也可指定单一来源。程序读取赔率、让球后使用现有模型生成ABCD，界面显示来源。

更改场次、顺序、期号或来源会清空旧ABCD并重新获取。旧请求返回不会覆盖新输入。获取失败后，须手动重新填写5位A/B/C/D才能生成；也可点击“重新拉取ABCD”。

澳客通过北单奖金计算页读取普通欧赔和让球，严格核对选中期号，不使用开奖SP或赛果。历史页可能返回405，页面结构变化、数据缺失或网络失败均进入手动输入流程。日期转期号从500真实期号列表查找，检查一期内所有比赛日期；失败时可直接输入5位期号。

底部固定提供“获取 ABCD”按钮，与“生成”并列，滚动后仍可使用。

## 新增9个压缩条件

以下条件仅统计主场原始彩果3/1/0，顺序与输入一致，固定场不参与。每项填写“最小值-最大值”，包含边界；留空关闭。所有启用条件须同时通过。

| 条件 | 5场可填范围 | 说明 |
| --- | --- | --- |
| 平的总场数 | 0–5 | 1出现的次数 |
| 负的总场数 | 0–5 | 0出现的次数 |
| 最长连续胜 | 0–5 | 最长连续3的长度 |
| 最长连续平 | 0–5 | 最长连续1的长度 |
| 最长连续负 | 0–5 | 最长连续0的长度 |
| 彩果种类数 | 0–3 | 实际出现的不同彩果数；只允许0会排除全部组合 |
| 彩果和值 | 0–15 | 原始彩果相加，不是ABCD判定值之和 |
| 隔场回返次数 | 0–3 | 连续三场首尾相同、中间不同；31313计3次 |
| 胜负直接切换次数 | 0–4 | 相邻30或03计1次 |

例如“最长连续胜”填0-2会排除连续3场及以上胜的组合；填2-2只保留最长连续胜恰为2场的组合。未出现该彩果时最长连续段为0。

新增条件在原有条件之后执行。界面及TXT显示各项实际删除、剩余注数；TXT附已启用范围。快捷配置和历史记录保存新增条件，旧配置默认不启用这些条件。

## 默认条件

筛选范围、Q删除注数、禁止4位置、新增9项条件和固定单选彩果自动保存。首次升级从最近一次成功计算迁移。重新获取ABCD不会覆盖这些条件。“胜的总场数”条件已经停用，旧记录中的0–3等范围会被忽略并从保存值清除。

主场、固定场、上次结果的场次号每次启动留空，重新填写。ABCD也不沿用旧值。

## 有依据的最终减半

默认“ABCD综合评分减半”：先执行所有现有条件，再按生成ABCD时使用的泊松模型胜平负概率给主场组合评分，保留剩余实际注数中评分较高的一半。奇数向上取整，101注保留51注。固定场选项等权。

若页面发布有效的胜平负投注占比，可用0–30%的辅助权重混合单场模型评分；默认15%，只是可调的启发式设置，未经过历史回测校准。当前页面缺失投注占比时自动跳过，真实投注金额与历史战绩统计未取得。手动ABCD且没有模型概率时，明确使用ABCD判定值倒数归一化的估计分数。

可切换“ABCD加权随机减半”：评分越高，被保留机会越大；输入、评分及随机种子相同时结果可复现。也可选择原有“Q排序减半”或关闭。

TXT记录评分依据、单场评分向量、随机种子及减半前后注数。首页主场模型覆盖率不含固定场命中率，也不是完整TXT的中奖概率。

## 评分压缩比例按钮

“去掉最高50%”“去掉最高30%”“去掉最高20%”按钮按综合评分从高到低删除对应比例，分别保留评分较低的50%、70%、80%。点击按钮会切换为综合评分模式，点击生成应用该比例。保留注数向上取整，例如101注分别保留51、71、81注。比例自动保存，不会在上次结果上反复叠加删除。旧配置默认去掉最高50%。

## 未命中原因自动分析

只需输入5个场次号。程序优先从历史记录取得当时的期号和ABCD，再从500取得实际彩果，并依次判断基础条件、乘积Q删除和最终评分压缩。若主场彩果已保留，会提示继续核对固定全包场和固定单选场。没有对应历史筛选记录时，只报告能够确认的基础条件和Q阶段，不用当前赔率冒充当时评分。

## 全局操作按钮

页面底部新增“全局”菜单，在任意滚动位置都能匹配期号、获取ABCD、选择去掉最高评分比例、生成、分析未命中原因、清空条件、换随机种子和导出TXT。

底部同时常驻“分享TXT”按钮。生成结果后点击，会先创建带时间戳文件名的UTF-8 TXT文件，再打开苹果系统分享面板，可选择隔空投送、微信、邮件或“存储到文件”等系统提供的渠道。

分享TXT只包含最终注数和投注结果，不再包含筛选条件、评分依据、概率说明或各阶段统计。完整7场结果中，只要两行有6场相同，就合并剩余1场；合并后的行继续参与下一轮，递归到无法继续合并，并校验展开后与原始注数完全一致。
